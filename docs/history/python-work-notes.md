# 대화에서 함께 확인한 코드 작성·수정 내용

[전체 기록](index.md) · [README](../../README.md)

이 문서는 이전 상세 기록과 함께 대화에서 설명한 수정 이유를 찾아보기 위한 보충 기록입니다. 실제 실행 결과와 작성 안내를 구분합니다. 게임·과제·Git과 무관한 설정은 포함하지 않습니다.

## 메뉴와 터미널 입력 구분

- `print("=" * 40)`으로 구분선 길이를 정했습니다. 등호를 직접 40개 적는 대신 문자열 반복을 사용했습니다.
- `input()`의 반환값은 문자열이므로 메뉴를 `choice == "1"`처럼 비교했습니다.
- 프로그램이 종료된 PowerShell에 `2`를 입력하면 게임 메뉴를 선택하는 것이 아닙니다. `python main.py`로 실행하고 메뉴 입력 위치에서 번호를 넣도록 구분했습니다.
- 메뉴 입력 위치에 `python main.py`를 넣으면 메뉴 번호가 아니므로 안내가 나왔습니다.

## 클래스·객체·메서드 작성

- `classs`를 `class`로 수정하고 클래스 이름 뒤에 콜론을 넣었습니다.
- `__init__`은 init 앞뒤에 밑줄 두 개씩이며, `def __init__(self, question, choices, answer):`로 작성했습니다.
- `def show(self):`의 콜론, 클래스 안의 메서드 들여쓰기를 확인했습니다.
- Quiz는 문제 공통 구조이고 `quiz1 = Quiz(...)`는 실제 문제 객체입니다. `quiz1.question`은 질문 속성, `quiz1.show()`는 질문·선택지를 출력하는 호출입니다.
- `quiz1.show()`와 `print(quiz1.question)`을 함께 실행해 질문이 두 번 나왔고, 개별 질문 출력을 정리했습니다.
- `check()`는 클래스 안에 두고, 시험용 print는 클래스 밖에서 호출했습니다. `check(2)`의 True와 `check(1)`의 False를 확인했습니다.

## 들여쓰기 오류와 중복 코드

- `elif` 아래 출력문을 들여 쓰지 않으면 `expected an indented block` 오류가 났습니다.
- 최상위 시험용 print 앞에 불필요한 공백을 넣어 `unexpected indent`가 났고 시작 위치를 맞췄습니다.
- if와 else는 서로 같은 위치, 각 분기의 실행문은 한 단계 안쪽에 놓도록 정리했습니다.
- 메뉴 1번 코드를 옮길 때 기존 분기를 수정해야 하며 같은 if 블록을 두 번 붙이지 않도록 확인했습니다.
- 메뉴 번호를 입력받기 전에 choice를 검사하는 코드를 넣지 않고, input 뒤의 기존 1번 분기 안으로 옮겼습니다.

## 문제·리스트·반복문

- Docker 컨테이너 실행 문제는 docker run, 정답 번호 1로 확인했습니다. Dockerfile 이미지 빌드는 docker build, 정답 번호 2입니다.
- Git commit 문제와 Git status 문제를 추가해 기본 다섯 문제를 만들었습니다.
- quizzes 리스트에 다섯 객체를 담고 len(quizzes)의 5를 확인했습니다.
- quizzes[0].question으로 첫 질문을 꺼내며 인덱스가 0부터 시작한다는 점을 설명했습니다.
- for에서 질문만 출력하다가 quiz.show()를 호출해 선택지도 표시했습니다.
- 반복문과 개별 show 호출을 함께 두면 중복 출력되므로 개별 호출과 시험용 판정 print 두 줄을 정리했습니다. check 메서드 자체는 그대로 남았습니다.

## 메뉴 연결·답 입력과 다음 단계

- 메뉴 앞의 for를 기존 메뉴 1번 분기 안으로 옮겼습니다. 메뉴 1 선택 후 다섯 문제 표시·메뉴 복귀를 확인했습니다.
- quiz.show()와 같은 깊이에 user_answer = input(...)을 추가해 문제마다 답을 받았습니다. 답 입력 화면에서는 세 번째 문제에 답한 뒤 네 번째 문제가 나온 것까지 확인했습니다.
- 문자열 입력과 정수 정답의 차이를 설명하며 str(quiz.answer) 비교를 안내했으나, 확인 당시 저장 파일에는 채점 분기가 없었습니다. 안내와 구현 완료를 구분합니다.
- 2026-11-17에는 1~4 번호를 받을 때까지 다시 묻는 while·strip·in·break 코드를 안내했습니다. 현재까지 실행 결과를 받지 않았으므로 완료 기록이 아닙니다. 다음은 입력 검증 후 Quiz.check 연결과 점수 계산입니다.

## Git 학습에서 다룬 내용

- .gitignore 내용은 터미널 명령이 아니라 파일에 넣는 제외 규칙입니다.
- add는 변경 준비, commit은 로컬 이력 기록, push는 원격 업로드라는 차이를 확인했습니다.
- add 뒤의 LF/CRLF 경고와 실제 스테이징 여부를 구분하고 diff --cached로 확인했습니다. 문서를 고치면 다시 add해야 최신 내용이 준비됩니다.
- commit 메시지는 앞뒤 따옴표로 묶으며 따옴표가 맞지 않아 PowerShell이 >>로 기다릴 때 Ctrl+C로 입력을 취소하는 방법을 안내했습니다.
- 작성자 이름·이메일 설정과 GitHub 로그인 계정을 구분했습니다. local과 global 적용 범위, 하위 폴더와 별도 저장소의 차이를 설명했습니다.
- remote가 비어 있던 상태에서 origin을 등록하고 최초 push로 추적 관계를 설정했습니다.
- 노트북과 공용 컴퓨터는 처음 clone, 작업 시작 전 상태 확인·pull, 마무리 시 commit·push하는 순서로 설명했습니다.
